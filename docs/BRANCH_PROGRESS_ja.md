## 各研究開発ブランチの詳細分析

### 1. `w4a4-accel` & `w4a8-accel`：ハードウェア Tensor Core 算子基盤
- **使命**：従来の逆量子化による演算オーバーヘッドを排除し、純粋な Rust から Ampere ネイティブ Tensor Core 命令を直叩きする。
- **ブレークスルー**：
  1. **NVRTC JIT ランタイム**：Rust FFI 経由で `libcuda.so.1` と直結し、`nvcc` インストール不要で PTX アセンブリを即時コンパイル。
  2. **`m16n8k64` ネイティブ INT4 MMA**：Warp 内 32スレッドが符号付き 4-bit 行列乗算 ($16 \times 8 \times 64$) を単一命令で実行し、**135.24 TOPS** を発揮。
  3. **4D プリスウィズル配置**：重みを $[K/64, N/8, 16, 32]$ に事前配置し、実行時転置ゼロを達成。
  4. **Hadamard-256 ConvRot 変換**：アテンションのダイナミックレンジを均等化し、数理的厳密性を維持。

### 2. `phase1-scratch`：メモリプール固定と抗断片化防衛
- **使命**：47層 DiT の反復計算において Candle および CUDA の動的確保によるメモリ断片化と偽の OOM を絶滅させる。
- **ブレークスルー**：
  1. **CUDA Stream メモリプール固定**：OS との頻繁なページ返却・再取得を根絶。
  2. **全ライフサイクル静的 Scratchpad**：中間テンソル確保を事前割り当てブロックに統合。
  3. **動的確保ゼロ化**：単一ステップの微小確保を **2,256回から 0回** に削減。

### 3. `phase2-streaming`：3層非対称ストリーミングオフロードエンジン
- **使命**：9.6 GB の 14B モデルを 8GB 以下のコンシューマ GPU 上で安定動作させる。
- **ブレークスルー**：
  1. **VRAM-RAM-Disk 3層非対称階層**：
     - VRAM：2 ~ 28ブロックを常駐させ 0 ms アクセス。
     - Host RAM：14 ~ 40ブロックをシステムメモリに配置 (~12 ms PCIe 4.0)。
     - NVMe Disk：5ブロックを高速 SSD からオンデマンド取得。
  2. **非同期ダブルバッファリング**：計算と H2D 転送をオーバーラップさせ、ブロック $N$ の GPU 計算中にブロック $N+1$ を先行フェッチ。

### 4. `phase4a-quality` & `fork002`：品質検証アーカイブベースライン
- **使命**：激しい高速化検証の最中においても、不動の数値収束ベースラインを担保する。
- **成果**：
  1. **GitHub 公開ブランチ**：GitHub 上で **`phase4a-quality`** として保存され、1080p 12秒でコサイン類似度 0.999956、相対 L2 誤差 0.9436% を実証したコードを永続保持。
  2. **R2D オフライン Git バンドル**：内部開発ブランチ `fork002` を `/mnt/R2D/repo_backups/h3-dit-w4a4_fork002.bundle` に完全パッケージ化。

## Main 本線：統合型 Phase 3 & Phase 4 高解像度エンジン

`main` 本線は上記すべての成果を統合し、1080p におけるメモリ爆発と長系列数値ドリフトを解決しました：

### 1. 適応型アテンションヘッドグルーピング ($O(S^2)$ 抑制)
- **$S \le 60,000$ (3秒 / 49k)**：適応型 2グループ (28ヘッド/グループ)、100% GPU ゼロコピー。
- **$60,000 < S \le 100,000$ (5秒 / 80k)**：適応型 7グループ (8ヘッド/グループ)、GPU インプレース列コピー。
- **$100,000 < S \le 150,000$ (8秒 / 121k)**：適応型 14グループ (4ヘッド/グループ)、256バイト整列、GPU インプレース列コピー。
- **$S > 150,000$ (12秒 / 182k)**：適応型 28グループ (2ヘッド/グループ)、時間差 VRAM 管理。

### 2. デュアルインプレース CUDA 残差算子
- **`gate_add_inplace` & `add_inplace`**：メモリ領域上での直接加算により、94回発生していた 1.96 GB の一時テンソル確保を完全排除。
- **`copy_slice_col_inplace`**：GPU 上の直接列コピーにより、1,316回の一時テンソル断片化を解消。

### 3. 時間差 VRAM ライフサイクル管理
$S > 85,000$ の長系列において：
- アテンション確保前に中間変調値 $n1$ を早期解放し、2.0 GB の VRAM を即時回収。
- `dev.synchronize()` を明示的に呼び出し、Candle のメモリプールをデフラグ。
- `--vram-blocks 2` と連動し、使用可能 VRAM を 3.90 GB 以内に固定。

### 4. Phase 3.2 8秒 VRAM 閾値精密チューニング (純前向き計算 607秒到達)
1080p 8秒 ($S=121,041$) において、保守的だった CPU オフロード判定を撤廃し、8GB 内の残り 1.2GB を解放。`mid_q,k,v` を 100% GPU に常駐させ、純前向き計算を 626.38秒から **607.34秒** に短縮 (19.04秒短縮)。

### 5. Phase 3.2b-lite：Pinned Host グループ主順序ストリーミング & 128-bit ベクトル化 Gather
リサーチャー `rc001` (Claude Sonnet 5.5) の仲裁・指導により、1080p 12秒 ($S=182,581$) における CPU メモリ重複ボトルネックを克服：
- **GPU 常駐アクティベーション $x$**：層ごとに 3.9GB の PCIe 双方向帯域を節約；
- **常駐 Pinned Host バッファ (`[G=28, S=182581, W=256]`)**：2.62GB のページロックメモリ (`PORTABLE`) を一括確保し、GPU からの非同期 DMA (実測 24.19 GB/s) で直書き。CPU 側の `Tensor::cat` 結合オーバーヘッドを完全消滅；
- **128-bit (`uint4`) ベクトル化インプレース Gather (`gather_groups_to_rows_inplace`)**：226.43 GB/s の超高帯域で 0.518ms 内に列ベクトルを再構成し、Out-Linear GEMM と完全オーバーラップ；
- **結果**：80W 功耗下で 12秒の所要時間を 1454.97秒から **1376.29秒** へ短縮 (78.68秒短縮、L2 diff=0.0, Max diff=0.0)。

### 6. Phase 3.3：ハードウェア電力とクロックの限界解放 (Dynamic Boost 125W + 1800MHz)
Intel LAPKC71F の静的 80W 制限を突破：
- `/usr/bin/nvidia-powerd` を起動し Dynamic Boost 125W を解除；
- `nvidia-smi -lgc 1500,1800` でコアを高周波に固定し、クロック低下を完全解除；
- 12秒の所要時間を 1376.29秒から **1155.95秒** へ大幅圧縮。

### 7. Phase 3.3b：非量子化アテンション品質フォールバック基準 (Unquantized-Attention Quality Fallback)
- **絶対的数学真値の維持**：全47層のアテンション計算を純粋な FP16/BF16 で保持し、INT8 量子化ノイズを完全ゼロ化（相対 L2 誤差 0.000%）。
- **実機パフォーマンス**：1080p 12秒で 1100秒の壁を破り **1092.05秒** を記録。

### 8. Phase 4A：FlashAttention-4 対数領域遅延リスケーリングエンジン
リサーチャー `rc001` と `sp001` の共同導出により `src/attn8.rs` に導入：
- **FP32 アキュムレータ (`f32.f16.f16.f32`)**：47層・18万トークン超にわたる仮数部吸収を根絶；
- **FlashAttention-4 対数領域遅延リスケーリング ($\tau = 4.0$)**：
  Softmax 最大値のステップ差分 $\Delta m > 4.0$ を超えた場合のみリスケーリングを実行し、無駄な乗算の **95% 以上** を回避；
- **実機パフォーマンス**：
  - 1080p 8秒を **537.01秒** に短縮 (純前向き計算で 13.58% 加速、コミュニティ版 W4A8 より 283.31秒高速)；
  - 1080p 12秒で **1152.13秒** を安定達成し、Phase 3.3b 黄金基準に対して **0.999956**（99.9956%）のコサイン類似度と **0.9436%** の相対 L2 誤差を実証。

## 手書き 100% Pure Rust W4A4 vs コミュニティ版 W4A8 ダウンロードモデル実機対決 (8秒 1080p 1-Step 対決)

手書きハードウェア級算子の優位性を客観的に実証するため、同一の 1080p 8秒入力条件のもと、オープンソースコミュニティ版（枝刈り・混合量子化 Safetensors モデル）と同一環境で実機比較検証を行いました：

| 評価指標 | コミュニティ版 W4A8 混合量子化 (Triton Sol-Attn + ChunkMLP) | 手書き 100% Pure Rust W4A4 (Phase 4A Lazy Rescaling) | 優位性 / 品質評価 |
|---|---|---|---|
| **モデル重み・形式** | `minimax_h3_fl2va_pruned_w4a8_mixed.safetensors` (12 GB) | `minimax_h3_fl2va_w4a4_preswizzled.gguf` (9.6 GB) | **ファイルサイズ 20% 削減** |
| **ランタイム依存関係** | Python 3.12 + PyTorch 2.10+cu130 + Triton + ComfyUI | 100% Pure Rust 単一静的バイナリ (`server_9412`) | **Python 完全不要 / 外部動的ライブラリ不要** |
| **1080p 8秒 所要時間 (1-Step)** | **820.32 秒** (13分40秒) | **537.01 秒** (8分57秒) | **手書き版が 283.31秒高速 (1.53倍高速 / 34.5% 時間削減)** |
| **ピーク VRAM 使用量** | 5.03 GB (割当) / 5.22 GB (確保) | 5.39 GB (固定 GPU プール) | 8GB GPU 上で完全安全動作 |
| **数値的安定性** | NaN: 0 / Inf: 0 | `NaN: 0, Inf: 0` | 完璧な数値収束 |
| **コサイン類似度 (Cosine)** | 1.000000 (自己対比基準) | **0.999668** (99.97% 高度収束) | アーキテクチャ間極めて高い忠実度 |
| **相対 L2 誤差** | 0.00% | **2.5757%** | 業界基準の 5% を大幅にクリア |
| **ノルム相対誤差** | 183618.82 | 183656.64 (**0.020593%**) | ビットレベルのエネルギー保存 |

**アーキテクチャ深層分析：なぜ手書き純 Rust W4A4 がコミュニティ版 W4A8 を圧倒するのか？**
1. **ネイティブ MMA 命令の直接発行**：Rust エンジンは NVRTC を経由して Ampere `m16n8k64` INT4 Tensor Core 命令を GPU に直接発行し、4D プリスウィズル配置によって Warp がゼロコピーで消費します。逆量子化や転置が一切発生しません。
2. **ChunkMLP メモリ再確保の完全排除**：Python/PyTorch 実装では超長系列（$S=121,041$）時に `ChunkMLP chunks=4` を強いられ、膨大なスライス切り出し、テンソル結合、GC 停止が発生します。手書き Rust 版は静的 CUDA Stream プールとインプレース残差カーネルにより、実行中の動的メモリ確保がゼロです。
3. **FlashAttention-4 対数領域遅延リスケーリング**：内蔵の `attn8.rs` は $\tau=4.0$ によるステップスキップ型リスケーリングを備え、アテンション内部ループの無駄な乗算の 95% を削減しています。

## 次世代ロードマップ：リサーチャー仲裁方針

WebLLM Farm のリサーチャー（`rc001` - Claude Sonnet 5.5 および `sp001` - AI Studio 4 Argon）による次期マイルストーン：

1. **アテンション二次関数モデリング**：
   - 12秒において、Attention 計算が全実行時間の **85% 超 (~1150秒)** を占める。
   - Host へのオフロードオーバーヘッドは **130秒 ~ 160秒 (約 10%)**。
2. **開発ルート選定**：
   - **ルート B+ (GPU 単独 INT4 事前量子化チャネル - 推奨)**：Block 0 で $n1$ を、Blocks 1..46 で $mid_{q,k,v}$ を INT4 に事前量子化し早期 drop。ピーク VRAM を **3.39 GB** に抑え、12秒の完全 GPU 完走により 450秒 ~ 550秒短縮。
   - **ルート A (Pinned 2D DMA ダブルバッファリング - フォールバック)**：2.62 GB の固定メモリを再利用し、グループ主順序 $[G][N][256]$ DMA 転送によって通信オーバーヘッドを隠蔽。
