## ブランチトポロジーと使命マトリクス

制約の厳しいコンシューマ向け GPU（RTX 3070 8GB / sm_86 / 80W TGP）において、極限の推論速度とクリーンなコードベースを両立するため、個別課題に特化したブランチ運用を経て `main` 本線へと統合されました：

```
                    [ アップストリーム：h3-rs (apiplant) ]
                                  |
            +---------------------+---------------------+
            |                     |                     |
     [ w4a4-accel ]        [ phase1-scratch ]    [ phase2-streaming ]
   (ハードウェア INT4 MMA)   (メモリプールと断片化防止) (3層ストリーミング)
  - m16n8k64 PTX JIT 実行   - CUDA Stream 閾値ロック   - VRAM:2/RAM:40/Disk:5
  - 4D Pre-Swizzled 配列    - 静的 Scratchpad バッファ - PCIe 4.0 非同期双方向
  - Hadamard-256 ConvRot    - 2,256回の確保をゼロ化    - 8GBで14Bモデル稼働
            |                     |                     |
            +---------------------+---------------------+
                                  |
                                  v
                               [ main ]
                    (Phase 3 量産型統合エンジン)
                   - 1080p フルスペクトル (3s, 5s, 8s, 12s)
                   - インプレース残差加算 (1.96GBの冗長確保を排除)
                   - インプレース列コピー (`copy_slice_col_inplace`)
                   - 適応型ヘッド分割 (56 -> 28 -> 14 -> 2)
                   - 時間差 VRAM ライフサイクル管理
```

## 各研究開発ブランチの詳細分析

### 1. `w4a4-accel` & `w4a8-accel`：ハードウェア Tensor Core 演算基盤
- **主たる目的**：レジスタ内で INT4 を FP16 に逆量子化するオーバーヘッドを排除し、Pure Rust 環境から Ampere Tensor Core の生命令を直接発行。
- **ブレークスルー**：
  1. **NVRTC JIT ランタイム直接連携**：Rust FFI 経由で `libcuda.so.1` とリンクし、起動時に PTX アセンブリを直接コンパイル。
  2. **`m16n8k64` ハードウェア実行**：Warp 内 32 スレッドが単一命令で $16 \times 8 \times 64$ の符号付き 4-bit 行列積を実行し、RTX 3070 上で **135.24 TOPS** を発揮。
  3. **4D プリスウィズル (Pre-Swizzled) 変換**：重みを $[K/64, N/8, 16, 32]$ 形式に事前配置し、ハードウェアレジスタバンク競合を完全排除。
  4. **Hadamard-256 回転変換**：アテンション QK 射影における数値ダイナミックレンジを保持。

### 2. `phase1-scratch`：メモリプール化と断片化防止機構
- **主たる目的**：47層の DiT 反復計算中に生じるアロケータの頻繁な動的確保によるメモリ断片化および OOM クラッシュを根絶。
- **ブレークスルー**：
  1. **CUDA Stream メモリプールのロック**：メモリ確保上限を固定し、OS との頻繁なページ返還・要求を停止。
  2. **静的 Scratchpad 領域**：すべての中間テンソルを事前に確保された静的バッファ上で再利用。
  3. **微小メモリ確保の完全排除**：ステップあたり **2,256 回発生していた微小確保をゼロに削減**。

### 3. `phase2-streaming`：3層非対称ストリーミングオフロード
- **主たる目的**：9.6 GB の 14B パラメータモデルを $\le 8\text{ GB}$ の一般家庭用 GPU 上で動作可能にする。
- **ブレークスルー**：
  1. **VRAM-RAM-Disk 3層メモリ階層**：
     - 第1層 (VRAM)：2〜28 ブロックを常駐配置しゼロ遅延計算。
     - 第2層 (Host RAM)：14〜40 ブロックを保持し PCIe 4.0 経由で高速転送。
     - 第3層 (NVMe SSD)：5 ブロックをオンデマンドでストリーミング。
  2. **ダブルバッファリング非同期リング**：GPU が層 $N$ を計算中に、PCIe 経由で層 $N+1$ を先行フェッチし、転送遅延を完全に隠蔽。

## Main 本線：統合型 Phase 3 高解像度エンジン

`main` 本線は、上記3ブランチの成果を結集し、1080p における二次関数的メモリ爆発を克服：

### 1. 適応型アテンションヘッドグルーピング ($O(S^2)$ 抑制)
シーケンス長 $S$ の拡大に伴い、8GB GPU でのメモリ衝突 ($4.58\text{ GB} > 3.90\text{ GB}$) を回避：
- **$S \le 60,000$ (3秒 / 4.9万 tokens)**：2グループ (28ヘッド/組)、完全 GPU ゼロコピー。
- **$60,000 < S \le 100,000$ (5秒 / 8.0万 tokens)**：7グループ (8ヘッド/組)、GPU インプレース列コピー。
- **$100,000 < S \le 150,000$ (8秒 / 12.1万 tokens)**：14グループ (4ヘッド/組)、256バイトアライメント、インプレース列コピー。
- **$S > 150,000$ (12秒 / 18.2万 tokens)**：28グループ (2ヘッド/組)、時間差 VRAM ライフサイクル管理。

### 2. デュアル・インプレース CUDA 残差オペレータ
- **`gate_add_inplace` & `add_inplace`**：47層における **94回の 1.96 GB テンソル動的確保をゼロ化**。
- **`copy_slice_col_inplace`**：`.narrow()` を置き換え、アテンション出力をターゲットテンソルへ直接書き込み、1,316回の断片化を撲滅。

### 3. 時間差 VRAM ライフサイクル管理
$S > 85,000$ の長大シーケンスに対し：
- アテンションバッファ確保前に中間変調テンソル $n1$ を早期解放し、2.0 GB を即座に返還。
- `dev.synchronize()` によりメモリプールを自動整理。

## 次世代ロードマップ：リサーチャー仲裁方針

1. **アテンション二次項の解析 ($t \approx aN + cN^2$)**：
   - 12秒においてアテンション計算量は **全体の85%以上 (~1150秒)**。
   - ホスト転送のオーバーヘッドはわずか **130秒〜160秒 (~10%)**。
2. **実装アプローチ**：
   - **アプローチ B+ (INT4 事前量子化完全 GPU 化 - 推奨)**：Block 0 で $n1$ を、Blocks 1..46 で $mid_{q,k,v}$ を事前に INT4 化して早期解放し、ピーク VRAM を **3.39 GB** に抑制して完全 GPU 化（450秒〜550秒短縮予測）。
   - **アプローチ A (Pinned 2D DMA)**：2.62 GB の固定メモリを用い、$[G][N][256]$ 配列で DMA 転送を高速化。
