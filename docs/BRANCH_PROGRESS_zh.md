## 各研发分支深度复盘

### 1. `w4a4-accel` 与 `w4a8-accel`：硬件级张量核心算子基石
- **核心使命**：彻底规避传统量化库在寄存器内将 INT4 反量化为 FP16 的算力瓶颈，在纯 Rust 运行时中直接调度 Ampere 原生 Tensor Core 指令。
- **关键突破**：
  1. **NVRTC JIT 运行时无痛集成**：通过 Rust FFI 直连 `libcuda.so.1`，启动时即时编译 PTX 汇编，无需宿主机安装庞大的 `nvcc` 工具链。
  2. **`m16n8k64` 原生硬件硬解**：Warp 内 32 线程单指令直接完成 $16 \times 8 \times 64$ 的有符号 4-bit 矩阵乘法，在 RTX 3070 上爆发 **135.24 TOPS** 满血算力。
  3. **4D 离线 Pre-Swizzled 重排版**：确立 $[K/64, N/8, 16, 32]$ 紧凑排布，单字节打包双 nibble，完全对齐 Ampere 寄存器 Bank，消除运行时转置开销。
  4. **Hadamard-256 旋转变换**：在注意力投影中平衡动态范围，严密守恒数值精度。

### 2. `phase1-scratch`：显存池化与抗碎片化防线
- **核心使命**：消灭 Candle 与 CUDA 动态分配器在 47 层 DiT 循环迭代中频繁分配导致的显存严重碎片化与 OOM 假死。
- **关键突破**：
  1. **CUDA Stream 显存池锁定**：强制锁定显存池阈值，杜绝驱动层频繁向操作系统还页与申请页。
  2. **全生命周期静态 Scratchpad 缓冲区**：将所有中间激活张量分配收拢到静态预分配池。
  3. **微小分配彻底归零**：将单步扩散前向过程中的 **2,256 次微小临时分配降至 0 次**，彻底稳固帧时间波动。

### 3. `phase2-streaming`：三级非对称流式加载调度引擎
- **核心使命**：打破大模型对大显存的垄断，让 9.6 GB 的 14B 参数模型平稳运行在 $\le 8\text{ GB}$ 的消费级显卡上。
- **关键突破**：
  1. **VRAM-RAM-Disk 三级不对称分层**：
     - 一级 (显存)：2 ~ 28 层常驻 GPU 显存，实现 0 延时瞬时计算。
     - 二级 (主机内存)：14 ~ 40 层驻留系统内存，走 PCIe 4.0 传输（~12 ms 延时）。
     - 三级 (NVMe 磁盘)：5 层按需从高速 SSD 流式拉取。
  2. **双流异步双缓冲 Ping-Pong 环**：利用计算流与 H2D 传输流的时间重叠，在 GPU 执行第 $N$ 层的同时，后台流水线静默预取第 $N+1$ 层，完全掩盖总线传输耗时。

### 4. `phase4a-quality` 与 `fork002`：质量验证归档基线
- **核心使命**：在激进加速探索的同时，建立不可动摇的数值收敛与质量回退基线。
- **关键落地**：
  1. **线上分支规范**：GitHub 远端将质量型分支统一命名为 **`phase4a-quality`**，承载 1080p 12s 经过 0.999956 余弦相似度验证的稳定代码。
  2. **R2D 离线持久化**：历史探索分支 `fork002` 打包为标准 Git Bundle 持久化保存在 `/mnt/R2D/repo_backups/h3-dit-w4a4_fork002.bundle`，确保零资产流失。

## Main 主干：Phase 3 与 Phase 4 终极高分辨率引擎

`main` 分支在汇聚上述分支成果的基础上，全力攻坚 1080p 高分辨率下的二次方显存爆炸与长序列累积漂移难题：

### 1. 自适应注意力头分组机制 ($O(S^2)$ 抑制)
序列长度 $S$ 扩大导致注意力开销呈二次方急剧攀升。在 8GB 显卡上，原生逻辑会因显存碰撞 ($4.58\text{ GB} > 3.90\text{ GB}$) 瞬间崩溃。`main` 主干引入自适应长度感知：
- **$S \le 60,000$ (3s / 4.9万 tokens)**：自适应 2 组（每组 28 头），100% 走 GPU 零拷贝通道。
- **$60,000 < S \le 100,000$ (5s / 8.0万 tokens)**：自适应 7 组（每组 8 头），走 GPU 原地列拷贝。
- **$100,000 < S \le 150,000$ (8s / 12.1万 tokens)**：自适应 14 组（每组 4 头），严格 256 字节对齐，走 GPU 原地列拷贝。
- **$S > 150,000$ (12s / 18.2万 tokens)**：自适应 28 组（每组 2 头），走错峰显存生命周期调度。

### 2. 双原地 CUDA 残差算子
- **`gate_add_inplace` 与 `add_inplace`**：取代外部分配相加，消除 47 层中 **94 次 1.96 GB 临时激活张量** 的显存分配。
- **`copy_slice_col_inplace`**：GPU 显存列拷贝算子，取代旧版 `.narrow()` 切片，将注意力计算结果直接写回目标大张量列偏移，消除 1,316 次张量切片碎片。

### 3. 错峰显存生命周期管理
针对 $S > 85,000$ 的超长序列，主干执行严格的显存错峰回收：
- 在分配注意力大张量前，提前释放中间调制值 $n1$，立即归还 2.0 GB 显存。
- 显式触发 `dev.synchronize()`，迫使 Candle 显存池整理碎片，确保可用显存稳定在 3.90 GB 红线内。

### 4. Phase 3.2 8s 显存阈值精准调优 (纯前向突破 607s)
针对 1080p 8s ($S=121,041$)，消除保守的 `mid_q,k,v` CPU 卸载判定阈值，释放 8GB 显存内最后 1.2GB 空间，保持 `mid_q,k,v` 100% 常驻显存零拷贝，单步纯前向耗时由 626.38s 大幅缩减至 **607.34s**（提速 19.04s）。

### 5. Phase 3.2b-lite：Pinned Host 组主序流式双缓冲与 128-bit 向量化 Gather 算子
由研究员 `rc001` (Claude Sonnet 5.5) 仲裁指导落地，攻克 1080p 12s ($S=182,581$) 下 CPU 巨量内存复制核心瓶颈：
- **$x$ 激活值常驻 GPU**：每层避免 3.9GB PCIe 双向往返带宽浪费；
- **常驻 Pinned Host Buffer (`[G=28, S=182581, W=256]`)**：跨 Step、跨 Block 单次分配 2.62GB 锁页内存（`PORTABLE`），以组主序由 GPU 异步 DMA 直写（实测 24.19 GB/s），彻底消灭 CPU 端 `Tensor::cat` 巨阵合并与 pageable 碎片开销；
- **128-bit (`uint4`) 向量化就地拼装算子 (`gather_groups_to_rows_inplace`)**：以 226.43 GB/s 超高带宽在 0.518ms 内就地重组 `[4096, 7168]` 列向量，与 Out-Linear GEMM 完全重叠；
- **实测成果**：在 80W 功耗墙下，12s 耗时从 1454.97s 缩短至 **1376.29s**（提速 78.68s，相比初始 1467.3s 提速 91s，L2 diff=0.0，Max diff=0.0）。

### 6. Phase 3.3：硬核功耗与时钟极限释放 (Dynamic Boost 125W + 1800MHz 锁频)
突破 Intel LAPKC71F 笔记本 VBIOS 静态 80W 功耗墙限制：
- 启动 `/usr/bin/nvidia-powerd` 解锁 Dynamic Boost 125W 动态功率上限；
- 配合 `nvidia-smi -lgc 1500,1800` 锁定核心高频，彻底解除原先被 80W 压低 35% 的核心时脉瓶颈；
- 单 Step 耗时实测大幅压缩（12s 从 1376.29s 暴降至 **1155.95s**）。

### 7. Phase 3.3b：未量化注意力质量回退黄金基准 (Unquantized-Attention Quality Fallback)
- **绝对数学真值守恒**：全 47 层的 Attention 投影与计算保持纯 FP16/BF16 精度，消除 INT8-QK 量化噪声，具备 100% 绝对数学真值保证（相对 L2 误差 0.000%）。
- **实测表现**：1080p 12s 耗时进一步击穿 1100s 大关，达到 **1092.05s**，作为不可动摇的质量验证黄金标杆。

### 8. Phase 4A：FlashAttention-4 对数域延迟重缩放引擎
由研究员 `rc001` 与 `sp001` 联合推导落地，在 `src/attn8.rs` 中引入两大革新：
- **FP32 累加器 (`f32.f16.f16.f32`)**：彻底终结跨 47 层、超 18 万 tokens 带来的 IEEE-754 尾数吸收与数值饱和；
- **FlashAttention-4 对数域延迟重缩放 ($\tau = 4.0$)**：
  仅当局部 Softmax 最大值跨步差 $\Delta m > 4.0$ 时才触发对输出寄存器的缩放，跳过 **>95%** 的在线乘法开销；
- **实测性能与精度**：
  - 1080p 8s 压至 **537.01s** (单步純前向提速 13.58%，相比社区 W4A8 快 283.31s)；
  - 1080p 12s 稳定跑出 **1152.13s**，与 Phase 3.3b 黄金基准达成 **0.999956**（99.9956%）余弦相似度与 **0.9436%** 相对 L2 误差。

**深层架构剖析：为何手搓纯 Rust W4A4 能够压倒社区 W4A8？**
1. **硬件 MMA 原生指令直通**：手搓 Rust 引擎通过 NVRTC 直接向 GPU 发送 Ampere `m16n8k64` INT4 Tensor Core 硬件指令，配合离线 4D 预重排（Pre-Swizzled）内存布局，计算时由 Warp 直接消费，零反量化、零转置；而社区 PyTorch 版即便使用 INT8，也需经过通用算子包装层。
2. **消灭 ChunkMLP 内存分配与拷贝抖动**：社区版在长序列（$S=121,041$）下因显存不足被迫采用 `ChunkMLP chunks=4`，每次分块前向产生大量的切片提取、张量拼接与显存分配抖动，外加 Python GC 锁；手搓 Rust 版采用静态 CUDA Stream 锁池与双原地残差算子，显存微分配为 0。
3. **FlashAttention-4 对数域延迟重缩放**：手搓版内建的 `attn8.rs` 融合了 $\tau=4.0$ 的对数域跳步重缩放，省去 95% 冗余乘法，使注意力核心算子比 PyTorch/Triton 调度更轻盈、延迟更低。

## 下一阶段前沿架构升级路线 (研究员仲裁方案)

全谱系实测闭环后，WebLLM Farm 专职研究员（`rc001` - Claude Sonnet 5.5 与 `sp001` - AI Studio 4 Argon）完成了下一代提速方案仲裁：

1. **注意力二次项物理建模**：
   - 二次项拟合表明，在 12s 下，Attention 计算算力占比超过 **85% (~1150s)**。
   - 主机 Offload 的额外开销仅为 **130s ~ 160s (~10%)**。
2. **演进路线规划**：
   - **方案 B+ (INT4 预量化全 GPU 通道 - 核心推荐)**：在 Block 0 将 $n1$、在 Blocks 1..46 将 $mid_{q,k,v}$ 预量化为 INT4 并提前 drop，峰值显存严格压在 **3.39 GB** 内，使 12s 全程 100% 常驻 GPU，预计可削减 450s ~ 550s。
   - **方案 A (Pinned 2D DMA 双缓冲 - 保底方案)**：重用 2.62 GB 锁页内存，采用组主序 $[G][N][256]$ 进行连续 DMA 传输，掩盖数据搬运延时。
